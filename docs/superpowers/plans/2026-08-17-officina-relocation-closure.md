# Officina relocation closure implementation plan

> **Execution:** Subagent-driven, with one scoped review after each remaining commit.

**Goal:** Make the existing relocation command complete the mechanical blueprint consequences of a source move in one preflight and one atomic application.

**Architecture:** Retain the current in-memory `ChangeSet`. Materialize its projected files in one temporary shadow repository only because the existing blueprint synchronizer requires filesystem input. In that shadow, update README-only Officina package initializers in the certification basis, run the canonical synchronizer, and load the canonical graph. Reconcile only those generated bytes into the `ChangeSet`; do not add a second graph, tracer, validator, or certification system.

**Tech stack:** Python 3.13, pathlib, tempfile, PyYAML, pytest, existing Officina graph and blueprint synchronizer.

## Global constraints

- Manifest schema version 2 is the only supported path; Task 1 completed that migration in commits `eb09d348` and `289b8950`.
- This is a behavior-preserving relocation tool, not dependency discovery. Existing typed path/source/interface rewrites update declared dependencies; the canonical synchronizer updates generated dependency artifacts.
- Registration, package disposition, exports, caller authorization, and genuinely new dependency relationships remain explicit manifest policy.
- Preflight must not mutate the real worktree. Application publishes the already-validated `ChangeSet` once through the existing concurrent-byte guard.
- Preserve unrelated dirty files and executable modes.
- Do not modify certification, runtime tracing, repository validators, or visualization implementation.
- Do not add import facades, compatibility paths, installation, signing, certification, commit, or push to the relocation command.
- Every new module, type, and nontrivial helper needs a repository-standard explanatory docstring; `officina.refactor.__init__` remains a README-only file catalog with no exports.
- Errors and reports must name exact paths and actions so the command is usable without reading its implementation.

**Step 2: Implement one small closure module**

Use a narrow result and one public coordinator:

```python
@dataclass(frozen=True)
class MechanicalClosureResult:
    certification_basis_changes: tuple[str, ...] = ()
    generated_artifact_changes: tuple[str, ...] = ()
    validation_results: tuple[str, ...] = ()


def close_projected_relocation(
    changes: ChangeSet,
    manifest: RelocationManifest,
) -> MechanicalClosureResult:
    """Close deterministic blueprint artifacts without changing the real tree."""
```

Avoid an import cycle: `closure.py` may import `ChangeSet` and
`RelocationManifest` only under `TYPE_CHECKING`; its runtime code uses their
documented methods. Define a local `MechanicalClosureError` for actionable
closure failures. `relocation.py` imports the coordinator locally inside
`plan_relocation` and converts `MechanicalClosureError` to `RelocationError`.

The coordinator must:

1. Create a `TemporaryDirectory` and materialize `changes.projected_files()` from `ChangeSet.read_bytes()`.
2. Preserve `100644`/`100755` modes and included regular-file repository-internal relative symlink link text only when the resolved target remains an existing projected path; reject absolute, escaping, cyclic, and dangling included links with their exact paths. Exclude `.git`, `.codex`, `.agents`, caches, environments, build output, `.certificates`, and `.pooled-reviews`.
3. Parse `references/certification/certification-basis-roots.json` in the shadow. Existing move/path rewrites have already adjusted moved entries. Add each manifest `package_catalogs` initializer under `src/officina/**` only when its AST is exactly one module docstring. Keep entries sorted and unique. Reject a substantive initializer with its exact path rather than trusting it.
4. Snapshot shadow bytes/modes, run the copied canonical `skills/skill-maker/_rtx/_blueprint_syncer.py` once with `sys.executable`, `cwd=shadow_root`, schema version 6, explicit UTF-8 capture, and the shadow `src` prepended to `PYTHONPATH`, then run it once with `--check`.
5. Permit synchronizer changes only to generated blocks in `skills/*/SKILL.md` and `references/blueprint/runtime_dependencies.json`. Report and reject any other changed path.
6. Load `load_repository_blueprint_graph(shadow_root, schema_root=shadow_root / "references/blueprint", expected_schema_version=6)` after synchronization.
7. Reconcile exact allowed changed bytes and modes through `ChangeSet.write_bytes`; do not write to the real root.

Do not trace imports, infer dependencies, initialize Git, invoke validators, or reproduce synchronizer logic.
