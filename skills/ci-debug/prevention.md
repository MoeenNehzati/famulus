# Cross-platform prevention review

Conduct this as a report-only review: do not modify production code, tests, or suite selection until the user explicitly approves the prevention proposal. For each repaired matrix failure, explain the root cause as the interaction between a particular operating-system behavior and the affected production code or assumption; explain where the same assumption could cause similar failures later; search the normal local suite for tests of the affected production entry point and observable contract; and report how the proposed test would model the foreign-platform condition on the current system, what production path it would invoke, what it would assert, and why that assertion would catch the broader failure class. If an existing test already covers the class, report that no action is needed; if it owns the contract but lacks the observed case, propose augmenting that test or its parameterization; propose a new test only when no existing test can own the behavior. Do not copy an existing experiment into another test or add it to another suite merely to label it portable; propose suite-selection changes only when the normal local gate does not execute the coverage. After approval, any prevention test must exercise repository production code rather than a platform library or fixture in isolation. Add a narrow seam only when needed to pass an explicit path flavor, platform context, environment, or system operation through the production path. Examples include driving the production path normalizer with drive-letter, UNC, namespace-prefix, backslash, case-folding, and POSIX cases; running the real generator under CRLF conditions; invoking the real CLI under a restricted encoding; or exercising the actual installer or backend selector with injected home/config mappings, a clean home, missing executables, minimum Python versions, timezones, or UIDs. Keep native matrix coverage for behavior that depends on real OS APIs, executable formats, filesystem semantics, browser lifecycle, or platform performance.
